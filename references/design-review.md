# 分页演示设计计划与画面复核

新建或整体改版时把设计决定融入章节到页面的映射；局部改版只复核受影响页。不新增一套重复文档，也不默认要求用户批准每个布局。

## 编码前

- 写清会议读者、要形成的判断或行动、来源中的核心结论与事实边界。先保住保护词和覆盖关系，再决定视觉密度。
- 保留选定品牌、系统中文字体、页框与交互合同；在可变部分确定标题/正文/证据的字号角色、主色用途和每页阅读轴。
- 在映射中记录每页“主旨 → 信息关系 → 形式 → 理由”。同类案例、证据或比较页可以复用结构；章节关系变化时重新选型，不按页数轮换。
- 开场按材料选择：结论型突出判断与边界；机制型用真实节点与关系；证据型使用批准的真实截图或成果；比较型保持共同维度；路径型只表达真实先后。双栏机制封面是常用选项，材料不足时采用清晰文本，不补造机制。
- 复杂页可用简短 ASCII 草图标出标题、主证据、连接与移动顺序。编码前检查焦点是否来自当前材料，而不是种子里现成的网格或卡片。

## 渲染后

1. 在 1440×900、1366×768 检查最终文件，整体截图看页内焦点、页间节奏与同类页面的一致性；正常阅读尺寸看中文换行、图标签、证据、页码与导航。
2. 核对保护词、来源章节和独有事实，查看移动画面及实际键盘、滚轮、触摸、锚点/hash、打印与低动态行为。没有执行的项目保留为未验证。
3. 修正裁切和拥挤时优先调整结构、增加续页；保留正文 16px、可见字至少 14px、标题不超过 60px。短标题可一行，长标题按语义断行。
4. 删除没有分类、顺序、状态、边界或强调作用的眉题、数字、徽章、单词高亮、网格和框。工程网格仅在确有助于机制图阅读时保留。
5. 修正后重新检查影响页；共用样式或运行逻辑变化复核全部受影响页。优先改原规则与断点，避免覆盖补丁累积。交付说明只报告实际完成的检查，不把结构通过当成浏览器验收。

2026-10-06 参考了 Anthropic [frontend-design 的固定版本 41bbe19](https://github.com/anthropics/skills/blob/41bbe19/skills/frontend-design/SKILL.md)，吸收具体任务驱动设计、编码前计划、信息性装饰和画面复核的方法。它是方法参考，不要求安装 frontend-design，也不自动跟随上游更新；本技能的品牌、事实、字号、单文件和分页运行合同优先。

后续维护按需比较上游变化，记录采用版本和理由，不直接整份覆盖或引入与分页演示无关的视觉偏好。
